fix: portable bounded string copy and strict-build warnings

The ESP32-C6 firmware build passed on the first CI run of B1-B3; only the two
new host groups failed, both for portability reasons rather than logic:

- strlcpy() is provided by ESP-IDF and BSD but is not declared by glibc under a
  strict -std=c11 host build, so every application use failed to compile in the
  host tests while compiling fine for the target. Added firmware/main/app_str.{c,h}
  with app_strlcpy() and used it in the application sources and their tests. This
  is not a stylistic wrapper around an existing API: it exists so the firmware
  build and the host build agree on the same semantics (strlcpy semantics,
  always NUL-terminated, returns strlen(src)).
- The advertised-name printability check compared a plain `char` against
  unsigned constants, which is a sign-compare error under -Werror on a target
  where char is signed. It now compares an explicit unsigned char.

Also tightened the entity-capacity test: it previously never reached capacity
because APP_DEVICE_MAX (24) exceeds ha_core's 8-device limit. It now drives
ha_core past its own bound and additionally asserts that no Entity or binding is
left orphaned by a rejected insert.
